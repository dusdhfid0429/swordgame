# testgame 핸드오프 — 스프라이트 파이프라인 (2026-10-16)

## 배경
- 레퍼런스: 비룡 키우기(Cocos Creator 3.x 웹빌드) 리소스 구조 분석. 아트는 추출하지 않았고 매니페스트만 읽음.
- 핵심 패턴: 프레임 시퀀스 애니메이션(스켈레탈 X). 파츠별 아틀라스 1장 + SpriteFrame N + AnimationClip ~20 + 공용 AnimationGraph의 Variant.
  캐릭터는 9파츠(Clothes/Weapons/hair/hat/face/pants/glove/shoe/aura) 페이퍼돌 레이어링, 같은 캔버스·pivot·프레임수로 그려 Z순서로 겹침.
- 소팅 레이어: Map → Map_Fx → Entity_Back → Entity → Fx → Overhead → Top
- 리소스 배포: 내장 번들 최소 + 원격 PatchResource 번들(manifest.json 버전 해시로 핫패치)

## 데이터 포맷 (이 프로젝트 표준)
- `<name>.png` 아틀라스 (2의 거듭제곱, padding 2)
- `<name>.atlas.json`
  ```
  frames[name] = { index, rect{x,y,w,h}, offset{x,y}, sourceSize{w,h},
                   pivot{x:0.5,y:1.0}, trimmed, sockets[{name,x,y,nx,ny}] }
  ```
  offset = 트림된 조각을 캔버스에 놓는 좌상단 위치. pivot = 캔버스 하단 중앙(발).
  sockets = 시트에 찍어둔 마커(녹색/시안/연파랑 십자) 위치. 무기·이펙트 부착점.
- `<name>.clips.json`
  ```
  clips[clip] = { frames:[idx...], fps, loop, durations_ms|null, events:[{frame,name}], canvas{w,h} }
  ```

## 툴
- `spritify.py`  GIF/APNG/영상/이미지폴더/격자시트(--grid) → 아틀라스+JSON. 트림, 중복제거, 크로마키, 미리보기.
- `autosheet.py` 자유 배치 AI 시트 → 자동 분할. 배경색 자동, 격자선 제거, 마커→소켓, 행별 클립, 공통 캔버스.
  ```
  python autosheet.py sheet1.png sheet2.png -o out --name hero --label-margin 200 --preview \
      --rows clipA,clipB,clipC --rows clipD,clipE
  ```
  같은 클립명을 반복하면 이어붙임(줄바꿈된 긴 클립). `--debug`로 검출 박스 확인.
- `nanobanana_prompts.md` 생성 프롬프트 틀 (격자/셀/pivot/배경 고정).

## 이 저장소에 적용한 것 (v123, 2026-10-16)

- `assets/wuxia/`: 핸드오프 산출물 그대로 (wuxia.png는 256색 팔레트로 줄임 2.2MB→0.48MB, 눈에 띄는 차이 없음). `wuxia.atlas.json`의 `sockets`에 무기 클립 손 위치를 피부색 덩어리로 자동 추정해 넣었다(`auto:true`, 어림값).
- `tools/spritify.py`, `tools/autosheet.py`, `tools/nanobanana_prompts.md`, `tools/README_spritify.md`: 핸드오프 툴.
- `build.py`: `assets/<이름>/<이름>.atlas.json`이 있으면 png(base64)+장 표+클립을 `<script id="sheets">`로 묶는다. gamedata.json과는 분리(핫패치 데이터에 그림을 싣지 않는다).
- `src/r_sheet.js`: 시트 로더. `SHEETS[이름]={img,frames[{r,o,s,pv,sk}],clips{f,fps,loop},white}`, `sheetOk`, `sheetClip`, `sheetK`(서 있는 키를 원본 주인공과 맞춘 배율), `sheetXY`/`sheetSocket`(캔버스 좌표→발 기준), `drawSheet`.
- `data/anim.json`: 클립에 `a:"wuxia", clip:"<시트 클립>"` 형식 추가. 바인딩: 맨손 공격(punches·kicks·combo·palm_strikes, `atk.wx`), 맨손 회피(dodge)·달리기(run), 모든 무기의 운기조식·내공 수련(meditate), 수련 창 동작(`hero.base.train`: 근력 strength_1, 민첩 dash, 지구력 endurance, 내공 meditate, 폐관 waterfall_stance, 창안 pole_balance).
- `src/r_atlas.js`: `heroFrame`에 운기조식·수련 상태 추가(경공 다음 순위), `heroClip`은 시트가 안 읽혔으면 `<이름>Nb`→base로 물러난다, 공격은 `P.ssh`(시트 이름)로 구분. `src/r_fighter.js`: 시트 장은 `drawSheet`로 그리고 무기는 안 그린다. `src/g_garb.js`: 문파 옷 색을 시트에도 입힌다.
- 9파츠 페이퍼돌·원격 번들은 그대로 보류.

## v124 검·도·창·봉 공격 클립 (2026-10-16)

- 원본 시트의 손 마커는 autosheet 단계에서 거의 지워져 있어(소켓 비어 있음) 쓸 수 없었고, 피부색 추정도 손을 가린 장·손싸개 장에서 빗나갔다. 그래서 무기 클립 51장(sword_thrust/slash, saber_heavy/whirlwind, spear_1/2, staff_1/2)의 손 위치를 격자 렌더를 보며 직접 찍어 `wuxia.atlas.json`의 `sockets`에 넣었다: `hand`(무기 손·양손 자루는 앞손), `hand2`(뒷손), `aim`(한손 무기가 뻗는 방향 점).
- `r_atlas.js sheetWeaponLine(sh, fi, kind)`: 소켓 → 무기 선. 양손 자루(창·봉)는 두 손 가운데를 잡고 뒷손→앞손 방향, 한손 무기(검·도)는 hand→aim. `drawWeapon`에 검 그리기 추가(원본 시트는 검이 그림에 들어 있어 없었다). `r_fighter.js`는 시트 장에 소켓이 있으면 그 위에 코드 무기를 얹는다.
- `anim.json atk.wx`: 검 flat=sword_thrust·vert/diag/ult=sword_slash, 도 flat/diag=saber_whirlwind·vert/ult=saber_heavy, 창 flat/ult=spear_1·vert/diag=spear_2, 봉 flat=staff_1·그 외 staff_2. 궁은 두 번째 시트 그대로.
- 손 위치가 어색한 장이 보이면 `wuxia.atlas.json`의 그 장 `sockets` 좌표(캔버스 327×337 기준)만 고치면 된다. 사용자가 무기 시트(핸드오프 다음 단계 1)를 만들면 소켓은 그대로 두고 코드 무기 대신 파츠 장을 겹치면 된다.

## v125 무기 파츠 시트 (2026-10-16)

- 사용자가 무기 시트(`assets/wpn/source_sheet.png`, 마젠타 배경, 초록 마커=손 자리)를 만들었다. 검·도(칼집은 따로 조각)·창·봉·궁 각 6~8장(방향만 다름)과 권 장갑 한 줄.
- `tools/weaponsheet.py <시트> <출력 폴더>`: 마젠타 배경으로 조각을 나누고, 초록 마커(≥50px 덩어리)가 있는 조각만 무기로 삼는다(칼집·장갑 줄은 버림). 마커는 둘레 2px까지 가장 가까운 무기 픽셀로 메우고, 가장자리의 마젠타 번짐도 지운다. 주축(PCA)으로 양 끝을 찾고 마커에서 먼 쪽을 `tip`, 가까운 쪽을 `butt`로 둔다. 출력은 핸드오프 포맷(`wpn.png`, `wpn.atlas.json` sockets grip/tip/butt + pivot=grip, `wpn.clips.json` 클립 이름=무기 종류).
- 런타임 `r_sheet.js sheetWeaponDraw(kind, line, lk, flash)`: 무기 선의 각도에 가장 가까운 장을 골라 나머지 각도만 돌리고, 길이를 코드 무기와 같게(`WPN_LEN`, 155px 주인공 기준 아틀라스 px) 맞춰 grip을 손에 놓는다. `drawWeapon` 첫 줄에서 불리므로 주인공의 모든 코드 무기 자리(대기·달리기의 자루선, 공격 클립의 소켓, v119 창·봉 자세)가 자동으로 시트 그림으로 바뀐다. 시트가 없으면 예전 코드 무기 그대로.
- 검집·도집(사용자: "허릿춤에 비스듬하게"): 1~2줄의 마커 없는 짧은 조각(130px 미만)을 칼집으로 삼고, 같은 칸 칼의 손잡이 마커에 가까운 끝을 입(grip)으로 둔다. `drawSheath(kind, 허리x, 허리y)`가 허리 뒤쪽(시트 장은 캔버스 155,263, 옛 장은 frame 기준 ax−6, 높이 55%)에서 아래·뒤 60도로 걸고, 몸보다 먼저 그려 몸 뒤에 걸린다. 검객 원본 시트 장(검 대기·경공)은 그림에 칼집이 있어 건너뛴다.
- 안 한 것: 권 장갑(맨손 클립엔 손 소켓이 없다), 몹의 무기(코드 그대로). 무기 그림을 바꾸려면 시트만 다시 만들어 툴을 돌리면 된다.

## v126 대기와 액션의 크기 맞춤 (2026-10-16)

사용자: "대기 상태의 캐릭터 크기와 액션(이동·공격·경공) 때의 캐릭터·무기 크기가 달라 대기 때가 너무 크다". 실루엣을 재 보니 몸은 모든 장이 69~71px(달리기·공격 웅크린 자세 55~65px)로 같았고, 커 보인 것은 무기였다: 두 번째 시트 대기 장은 배율 K2(.7285)로 그리는데 무기 그림도 그 배율을 그대로 따라 .47 배율 장보다 55% 크게 나왔다. `r_sheet.js`에 `WPN_K`(부르는 쪽의 현재 장 배율)를 두고 `sheetWeaponDraw`가 `.47/WPN_K`로 되돌려, 어느 장에서 그려도 무기 화면 크기가 같다(`r_fighter.js`가 몸을 그리기 전에 `WPN_K=k`, 끝에서 `.47`). 줄별 몸 배율 보정 자리(`A2_ROWK`)는 비워 두었다. 테스트 t83 8번.

## v127 무기 공격 클립의 몸 크기 (2026-10-16)

사용자: "봉 공격 중에 크기가 작아지는 게 있어". 무기 그림은 장마다 같은 길이(61px 안팎)였고, 작아진 것은 몸이었다. 핸드오프 시트의 무기 공격 클립(staff·spear·sword·saber)은 맨손 클립보다 10~15% 작게 생성돼 있다(불투명 면적 1300 vs 1700, 서 있는 장 65px vs 대기 70px). 웅크린 장(staff_1 #69, staff_2 #76)은 50px까지 내려가 더 눈에 띄었다. `data/anim.json` `ANIM.sheetK`에 시트·클립별 몸 배율(봉 1.1, 창 1.12, 검 1.06, 도 1.06/1.1, dodge 1.12)을 두고 `sheetK(n, 장번호)`가 그 장이 속한 클립의 배율을 곱한다(`r_fighter.js`는 `sheetK(sh,fi)`). 손 소켓·무기선도 같은 k를 쓰므로 무기는 손에 그대로 붙고, 무기 크기는 `WPN_K`로 되돌리므로 변하지 않는다. 보정 후 서 있는 장 69~75px. 테스트 t83 1번(kStaff).
